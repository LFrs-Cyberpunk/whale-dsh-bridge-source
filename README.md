# Whale ↔ DSH Bridge

一个适用于鲸鲸（Whale）API 4 的 JavaScript 消息插件。它将鲸鲸收到的消息转发给本机的 DSH Bridge，由 DSH 生成回复。

鲸鲸继续负责微信消息接入、触发条件、@ 提及、黑名单等逻辑；DSH 负责生成回复。桥接失败时，插件会把本轮生成交还给鲸鲸自身的模型。

## 功能

- **消息桥接：** 通过兼容 OpenAI Chat Completions 格式的 HTTP 接口调用 DSH。
- **上下文传递：** 转发最近最多 12 条历史消息，每条历史消息最多保留 2,000 个字符，并附带当前消息。
- **角色设定同步：** 可选择将鲸鲸组装的系统提示词传递给 DSH。
- **自动回退：** DSH 超时、不可用或未返回有效文本时，交由鲸鲸自身的模型处理。
- **故障诊断：** 在插件数据目录中记录最近一次失败原因。
- **本地优先：** 默认连接到 http://127.0.0.1:57321。

## 工作原理

微信消息先由鲸鲸处理触发与过滤逻辑，再进入消息生成钩子。插件调用 DSH Bridge；成功时返回文本供鲸鲸发送，失败时交回鲸鲸自身的模型。

~~~mermaid
flowchart TD
  A["微信消息"] --> B["鲸鲸：消息触发与过滤"]
  B --> C["chat.generate"]
  C --> D["DSH Bridge：POST /v1/chat/completions"]
  D -->|成功| E["返回文本，由鲸鲸发送"]
  D -->|失败| F["回退至鲸鲸自身模型"]
  B -. "可选保存系统提示词" .-> P["chat.prompt"]
  P -. "保存到会话 state" .-> C
~~~

插件不会自行决定是否应该回复某条消息，也不直接负责微信消息发送。

## 安装

1. 下载仓库中的 whale-dsh-bridge 文件夹。
2. 按鲸鲸 API 4 插件的安装方式导入或安装该插件。
3. 确保本机的 DSH Bridge 服务已经启动，并提供兼容的聊天补全接口。
4. 找到插件数据目录中的 config.json，填写连接地址与令牌。
5. 向鲸鲸发送测试消息，确认回复由 DSH 生成。

> 本仓库仅包含鲸鲸侧的桥接插件，不包含 DSH Bridge 服务端。安装本插件不会自动安装或启动 DSH。

## 配置

插件首次读取不到有效配置时，会尝试在插件数据目录中创建 config.json。配置文件示例：

~~~json
{
  "url": "http://127.0.0.1:57321",
  "token": "YOUR_BRIDGE_TOKEN",
  "timeoutMs": 40000,
  "enabled": true
}
~~~

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| url | http://127.0.0.1:57321 | DSH Bridge 的服务地址 |
| token | 空字符串 | Bearer 认证令牌；为空时插件不会调用桥接 |
| timeoutMs | 40000 | HTTP 请求超时时间，单位为毫秒 |
| enabled | true | 是否启用桥接 |
| personaSource | 未设置 | 设为 whale 时转发鲸鲸系统提示词 |

如需让 DSH 使用鲸鲸自身的角色设定，可增加：

~~~json
{
  "personaSource": "whale"
}
~~~

启用后，插件会在 chat.prompt 阶段保存鲸鲸系统提示词，并在 chat.generate 阶段将其附加到发往 DSH 的系统消息中。仅设置 personaSource 不会改变 DSH 服务端的行为；最终采用何种角色设定，仍取决于服务端实现和配置。

## 请求格式

插件向以下接口发送 HTTP POST 请求：

~~~text
http://127.0.0.1:57321/v1/chat/completions
~~~

请求使用 Bearer Token 认证，JSON 请求体包含以下内容：

~~~json
{
  "model": "dsh",
  "stream": true,
  "messages": [
    { "role": "system", "content": "..." },
    { "role": "user", "content": "..." }
  ]
}
~~~

系统消息开头包含 [[WHALE-BRIDGE v1]] 格式的元数据封装，用于传递平台、聊天类型、聊天 ID、发送者 ID 和消息 ID。插件能够解析 Chat Completions 格式的 JSON 响应，以及常见的 SSE data: 响应帧。

虽然请求设置了 stream: true，插件仍会等待完整 HTTP 响应后再提取文本，不会向鲸鲸逐字转发流式输出。

## 故障排查

如果插件已经安装，但回复仍然由鲸鲸自身模型生成，请先检查插件数据目录中的 last-error.json。

| 现象或错误 | 可能原因 |
| --- | --- |
| 没有令牌 | config.json 未配置 token |
| 读配置失败 | 配置文件不存在、JSON 格式错误或无法读取 |
| timeout | DSH Bridge 未及时响应 |
| http_401 | 认证令牌不正确，或服务端拒绝认证 |
| http_409 | 服务端可能检测到消息 ID 冲突 |
| empty | 服务端未返回可解析的回复文本 |
| 插件开关关闭 | enabled 设置为 false |

还应检查：

1. DSH Bridge 是否正在监听配置的端口。
2. url 是否正确。
3. 服务端是否支持 /v1/chat/completions。
4. 插件是否拥有所需的 API 4 权限。
5. 服务端返回格式是否与插件解析逻辑兼容。

last-error.json 只保存最近一次失败记录，不是完整运行日志；成功调用不会自动清除旧错误记录。

## 安全与隐私

本插件声明了 system.full 权限，属于高权限插件。安装前请阅读源码并确认信任代码来源。

- 插件会将用户消息及部分聊天历史发送至配置的 DSH Bridge 地址。
- 开启鲸鲸角色设定同步时，系统提示词也会被发送。
- 默认使用本机回环地址，但可以将 url 改为其他地址；请核对目标服务和网络环境。
- 配置文件包含认证令牌，应限制其访问权限，避免公开分享。
- 使用 HTTP 连接远程主机时，通信不具备 HTTPS 提供的传输加密保护。
- 本仓库不包含 DSH Bridge 服务端，因此无法仅凭本仓库审计服务端的数据处理方式。

请勿将真实令牌、私人聊天记录或包含敏感信息的配置文件提交到 Git 仓库。

## 开发说明

本插件主要使用两个 Whale API 4 Hook：

- chat.prompt：将系统提示词保存到会话状态，不直接修改原有提示词。
- chat.generate：调用 DSH Bridge；成功时返回 { text }，失败时返回 {}，让鲸鲸继续自身的生成流程。

此外，插件导出了 run 函数以满足 API 4 的接口要求，但它不是可手动执行的工具插件。
